# 보안 런타임 구현 보고서 — 2026-07-15

## 범위와 결과

오늘 작업에서는 `SlackOps Safe DevOps Agent` 설계 검토에서 도출한 보안 런타임
제어를 구현했습니다. 로컬 워크트리의 구현과 저장소·대시보드 빌드 게이트 검증은
완료했으며, 아직 **커밋 및 배포 전** 상태입니다.

이 변경은 사용자가 PR diff를 검토한 시점과 에이전트가 나중에 작업을 실행하는
시점 사이의 변경(TOCTOU) 가능성을 막습니다. 또한 웹 대시보드를 공개된 승인
화면이 아닌 인증된 제어 플레인으로 전환합니다.

## 구현한 제어 항목

### 1. GitHub 인증 대시보드

- NextAuth GitHub OAuth로 대시보드 페이지, API, 서버 액션을 보호합니다.
- `GITHUB_ALLOWED_USERS` 로그인 허용 목록을 필수로 적용하며, 목록이 비어 있으면
  접근을 거부합니다.
- 로그인한 GitHub 계정을 대시보드 요청자·승인자로 감사 기록에 남깁니다. 기존의
  배포 시점 고정 승인자 식별자는 제거했습니다.
- 대화 및 대기 작업 API에도 인증 사용자 경계를 적용했습니다.
- 로컬 우회는 명시적으로 활성화했고 DynamoDB 엔드포인트도 로컬인 경우에만
  허용합니다. Vercel 배포에서는 사용할 수 없습니다.

### 2. 불변 실행 계획과 승인 연결

- PR 준비 단계에서 표준화한 `ExecutionPlan`과 SHA-256 계획 해시를 저장합니다.
- 계획에는 명령, 인자 해시, 바이너리 diff 해시, 변경 경로, 워크스페이스 루트,
  정책 버전, 실행 도구 체인, 합산 권한이 포함됩니다.
- 승인은 정확히 그 계획 해시를 기록합니다. 계획이 없거나 변경됐거나 다른 해시로
  승인된 경우 실행을 거부합니다.
- 실행 단계는 이미 스테이징된 변경의 커밋·푸시·PR 생성으로 제한했습니다.
  수정/쓰기/스테이징/체크아웃 도구는 사용할 수 없습니다.

### 3. 워크스페이스 및 실행 후 검증

- 워커는 설정된 표준 Git 워크트리 루트를 필수로 요구합니다.
- 변경 경로의 상위 경로 탈출, 절대 경로, 심볼릭 링크 탈출, 추적되지 않는 파일,
  승인 후 바이너리 diff 변경을 검증해 차단합니다.
- 전체 허용 도구 체인과 합산 권한은 승인된 계획과 일치해야 합니다. 도구 또는
  권한이 확장되면 실행을 거부합니다.
- 작업을 완료 처리하기 전, 생성된 GitHub PR의 diff를 가져와 승인된 diff 해시와
  정확히 일치하는지 확인합니다.

### 4. 승인 및 감사 강화

- Slack 승인 버튼은 `SLACK_APPROVER_IDS` 허용 목록을 요구합니다. 목록이 비어
  있으면 기본 거부입니다.
- SQLite와 DynamoDB 작업 저장소에 실행 계획 해시와 승인 해시를 저장합니다.
- 감사 기록에 구조화된 정책/계획 컨텍스트와 해시 체인 연결을 추가했습니다.
  DynamoDB 추가 기록에는 덮어쓰기를 막는 조건부 쓰기를 사용합니다.
- EC2 워커 서비스에 표준 워크스페이스 설정과 systemd 파일시스템 강화를
  적용했습니다. (`NoNewPrivileges`, system/home 보호, 쓰기 경로 제한, 제한적 umask)

## 완료한 검증

| 검증 | 결과 |
| --- | --- |
| `make check` | 통과: 테스트 367개, Ruff, mypy, 문서 예산 게이트 |
| `cd web && npm run build` | 통과: Next.js 프로덕션 빌드 및 TypeScript 검사 |
| `git diff --check` | 통과 |
| 로컬 대시보드 스택 | Docker 빌드·시드 완료, 인증 경로 구현 컴파일 및 로컬 API 스모크 검사 통과 |

새 테스트는 표준 실행 계획 검증, 경로 탈출 거부, 심볼릭 링크 교체 거부, 승인 후
diff 변경, 실행 도구 체인 확장을 다룹니다. 기존 워커·저장소·PR 명령·승인·감사·
대시보드 테스트도 새 계획 해시 불변식을 강제하도록 수정했습니다.

## 남은 수동 설정

Vercel Production에는 GitHub OAuth App 값, `AUTH_SECRET`, `GITHUB_ALLOWED_USERS`를
등록했고 실제 GitHub 로그인을 확인했습니다. `make vercel-deploy`는 루트 `.env`를
기준으로 이 네 값을 동기화해 재배포합니다.

`SLACK_APPROVER_IDS`는 EC2 SSM에 동기화했습니다. 남은 작업은 중지된 기존 EC2의
런타임 환경 파일을 갱신한 뒤, 허용·비허용 Slack 승인 버튼을 실제로 검증하는 일입니다.

세부 절차는 `docs/guide/kr/VERCEL_DEPLOY.md`,
`docs/guide/kr/SLACK_GUIDE.md`, `docs/runbooks/deploy-checklist.md`에 정리했습니다.
